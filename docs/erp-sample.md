# ERP sample

The catalog opens a synthetic inventory screen using the shared DataGrid, Inspector, FormField and OperationButton. Codes are strings, preserving leading zeroes. Quantities and KRW values are numeric properties, so WPF sorts on the underlying numbers. The shared numeric cell and header styles right-align them and request tabular numerals; actual support depends on the selected font and remains to be verified. The item code is enabled and read-only, while name and reorder quantity are editable drafts. Drafts are held per item while the window is open. Explicit save validates a required 1–80-character name and an integer from 0 through 100,000. Failure leaves applied values unchanged; success applies the captured draft only to this window's memory. The simulated delay is not a server call, and selection and editing are disabled or read-only while saving. Closing the window discards the sample state.

On Windows, `dotnet build VisionApp.Dev.slnx --no-restore` succeeded with zero warnings and errors. `dotnet run --project Operations.UiCatalog --no-build -- --verify-erp=artifacts/erp-check.txt` opens a WPF window and programmatically changes the actual text boxes, checks read-only state, required and range error bindings, draft preservation across selection, busy state, failure preservation, and success. `erp-sample.png` is a WPF render capture. This is not a keyboard, IME, screen-reader, real persistence, DPI or performance test. The example has no cancellation or server conflict handling; those would be application contracts rather than an implication of the sample save.
