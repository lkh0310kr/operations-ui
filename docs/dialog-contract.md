# DialogHost component

`DialogHost` is an in-window overlay with `Content`, `DialogContent`, `IsDialogOpen`, optional `InitialFocus`, `CanDismissWithEscape`, `CanDismissOnBackdrop`, size and padding properties, and a `DismissRequested` event. Set an accessible name, provide a clear target and consequence, and supply explicit actions. `InitialFocus` must be an enabled, visible, focusable element inside the dialog; otherwise the first eligible descendant is used. Opening remembers the current keyboard focus, disables the host's background content and cycles Tab navigation inside the dialog surface. Closing attempts to restore focus only if the original element remains visible, enabled and focusable. Stale queued focus changes are discarded after a rapid close or reopen. Long content can scroll. Escape and backdrop dismissal follow their respective properties; dismissing is not a business action or evidence of saving.

This control only covers and disables its own `Content`. To present a modal decision for a whole window, make the host cover that window's interactive content; it does not prevent interaction with unrelated windows or elements outside the host. Consumers must still supply and verify automation labels, appropriate initial focus, escape behavior and their own command/permission rules. Its behavior has not been certified with assistive technology.

On Windows, the solution built without warnings or errors. `--verify-dialog=artifacts/dialog-check.txt` opened actual WPF windows and programmatically checked background disabling, explicit initial focus, forward and reverse WPF focus traversal, open-dialog Light resource update, a routed Escape event, focus restoration, rapid open/close and the catalog example. It also checked that Primary Button string content uses the button foreground and an `AccessText` element. These are programmatic WPF checks, not physical Tab/Shift+Tab/Escape or screen-reader tests. `dialog-sample.png` is the WPF render capture. The separate SendInput interaction test still could not obtain a foreground window in this session and did not resolve the earlier mouse-click failure.
