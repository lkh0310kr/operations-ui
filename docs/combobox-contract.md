# ComboBox template increment

The shared template now supplies WPF's `PART_Popup` and `PART_EditableTextBox`, honors `IsEditable` and `IsReadOnly`, keeps item presentation in an `ItemsPresenter`, and uses a distinct control border. Focus and validation have separate, non-layout-changing overlays, so both can be shown at once. The catalog includes editable and invalid examples. `ComboBox.Text`, selection, commands, text composition and commit behavior remain owned by WPF and the application's bindings; the template does not write to a device or change binding update policies.

On Windows, the solution built with zero warnings and errors. The WPF `--verify-catalog` check confirmed the editor part, text propagation, simultaneous focus/validation, and a reopened popup's Light resources. The input harness sent actual A, F4, Down, Enter and Escape keys and observed text entry, selection and popup dismissal before the final alignment-only change. A later run after that change again passed those keyboard steps but failed the following mouse-button activation; subsequent attempts could not obtain a foreground window (`GetForegroundWindow` returned zero). The mouse regression is unresolved and must be retested in an interactive desktop session. This is not an IME, touch or screen-reader verification.

The catalog now swaps token and semantic-brush dictionaries while preserving control templates; its test verifies an open popup remains open and picks up the Light surface. A separate system-contrast regression checks that the Light semantic canvas returns after the contrast overlay is removed. This is not a guarantee for other consuming applications that replace the entire theme entry dictionary. Editable input, long localized values, actual Windows high contrast and IME composition still need broader testing. `combo-focus-validation.png` is a WPF render capture of the current focus and validation overlays.
