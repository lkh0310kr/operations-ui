# HMI sample and Trend component

The catalog's HMI button opens a Touch-density window using the same Foundation, StatusIndicator, Inspector and OperationButton resources as MES. Its data is synthetic and fixed. It simultaneously shows the last confirmed equipment state, disconnected connection, stale data and an active unacknowledged alarm. These are independent facts; a source policy would determine freshness in a real application. The example does not evaluate a universal timestamp threshold or connect to any device. The unavailable speed remains a dash instead of zero. The disabled command has an adjacent explanation and sends nothing. Sample acknowledgement changes only the sample acknowledgement flag, not the active alarm.

`Trend` is a non-interactive FrameworkElement for ordered `IReadOnlyList<TrendSample>` values with explicit `Start`, `End`, `Minimum` and `Maximum`. A sample contains a timestamp, nullable value and source quality. Missing, non-finite, uncertain or bad samples break the line; no interpolation or freshness calculation is performed. The consumer supplies axis labels, units, domain, quality and freshness context. Replace the list when updating it; mutation of an existing list does not automatically invalidate the visual. Set an accessible name and help text that summarize the time range, units, values and gaps; the image automation peer is not a substitute for an accessible data table. The control is informational, has no keyboard actions or commands, and renders an empty plot for an invalid domain or no samples. It uses dynamic theme brushes and clips to its viewport. It does not provide aggregation, zoom, panning, a legend, threshold assessment or data virtualization.

`dotnet build VisionApp.Dev.slnx --no-restore` passed with zero warnings and errors. On Windows, `dotnet run --project Operations.UiCatalog --no-build -- --verify-hmi=artifacts/hmi-check.txt` opened the WPF window and checked the Touch minimum height, disabled request, missing sample and acknowledgement/active independence in the sample model. `--hmi-snapshot=...` was run in both themes; `hmi-dark.png` and `hmi-light.png` are WPF render captures. These checks do not establish actual touch, screen-reader, keyboard, dynamic-theme transition, DPI or device behavior. The example does not yet include a reusable alarm list or a simulated request/response lifecycle; those remain open requirements.
